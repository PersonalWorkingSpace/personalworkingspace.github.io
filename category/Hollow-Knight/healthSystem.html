空洞騎士重現 - Health System

Nov 22, 2026 |Hollow Knight
GameMake
上次學完了 shader graph，這次回到基本的遊戲機制 - 血量系統，空洞騎士中血量 (面具) 綁定在魔力 (靈魂) 上，而靈魂得透過攻擊敵人才能獲取，這種設計間接鼓勵玩家積極進攻，是相當有巧思的一點，而血量系統的呈現也是充滿巧思，到處都有動畫與粒子系統，讓一個回血/受傷都有滿滿回饋感，這次實作的項目包含 - 面具系統、靈魂系統、回血/受傷狀態、以及靈魂圖騰。

Sprites

這次新增的 sprites 比較多，依用途整理如下:
  • 小騎士新增動作 - 包含受傷擊退 021.Recoil，以及回血的 050.Focus、051.Focus Get、052.Focus End。
  • 回血特效 - 包含 003.Focus Effect、004.Focus Effect End 與 005.Burst Effect。
  • 受傷特效 - 像是 hit_crack_simple、white_hit_particle 等擊退時的爆裂與粒子。
  • HUD 動畫 - 包含面具的 002.Health Idle、003.Health Break、004.Health Refill。
  • HUD 靜態圖 - 包含 HUD 主體、面具 (Ancient Mask) 以及靈魂球的填充圖 (Soul orb fills atlas)。
  • 場景物件 - 這次的場景換成了 Forgotten Crossroads，另外還有靈魂圖騰 (Soul Totems) 與尖刺 (Spikes & thorns)。
上述 sprites 可能會有紅框，可以透過此程式來移除。

Canvas UI

為了能夠產生出固定於畫面上的 UI，這邊先新增 canvas 並產生對應的物件:
  • Container - 這個基本上只是一張 Image 用來當成背景裝飾:
  • Soul - 疊加在 Container 之上實際的靈魂量，他其實也只是一般的 Image 但透過特殊 shader 以及 animation 才呈現出容器內流動的現象。
  • Masks - 用來管理底下全部 mask 的物件，每個 mask 就是獨立的 Image，血量的呈現是由此物件控管。
除了物件的生成，另外要注意的是 Canvas 的 Camera 設定，Render Mode 得選用 Screen Space - Camera，這是為了讓粒子系統能夠在 Canvas 上呈現，此外得額外新增一個 Orthangonal Camera 來專門拍攝 UI，因為 UI 並不需要考慮景深。

血量（面具）

血量由面具的數量來呈現，這邊的數量又由三個數字來控制:
  • 最大血量 - 遊戲允許玩家擁有的血量上限，這邊就是由 Masks 物件底下有多少個 Mask 決定的，可以說遊戲設計的當下就決定好了。
  • 當下上限 - 玩家當下的血量上限，由於遊戲進度決定，也就是找到多少張面具 + 初始面具，由於我們是直接把最大血量的 Mask 數都創造出來了，這邊就要把多出來的 Mask Deactivate 不要顯示。
  • 當下血量 - 玩家剩下的血量，超出的部分就會讓 Mask 動畫進入破碎狀態。
而每一個 Mask 都有其動畫狀態，IDLE 狀態是會每隔一段時間閃爍一次，( 當下上限 - 當下血量 ) 多出來的 Mask 會進入 broken 狀態，反之當下血量的 Mask 則都會設定 recover 狀態，所以一旦當下血量提升，本來破碎的 Mask 就會回復，然後自動轉為 IDLE 狀態。每次 recover 的時候，Mask 上下都會噴出粒子特效，這邊是透過 animation 的動畫視窗錄製，讓粒子系統在 recover 時自動轉成 active，此外有一點特別需要注意，這邊 sprite 是綁訂在 mask 物件，而上層的則是一個空物件，多切一層是因為動畫播放的時候需要調整 sprite 的座標，為了讓調整的座標形成相對座標才這樣設計的，不然每一個 mask 播放動畫時都會移動到相同的位置 XD。

遊戲中面具的IDLE 閃爍其實更複雜點，因為是每個 Mask 同步閃爍。

回血（Focus）

輸入與狀態

根據 sprite 的名稱，空洞騎士中的回血似乎被稱作 Focus，首先新增輸入動作 Focus，綁定鍵盤 A，並且需長按 0.1 秒 (Hold Time) 才會觸發 (短按則觸發復仇之魂)。接著新增 4 個回血狀態，流程如下:
HealStart → HealGet → HealCombo → HealGet → ...
HealStart、HealGet 都只是在播放回血的動畫，只是後者等待的時間比較短，而 HealGet 則是實際會觸發回血的狀態。只要放開按鍵就會進入 HealEnd，最後回到 Idle，這樣設定是因為連續回血的速度會比第一次來的快，鼓勵你一次回多一點。

回血規則

  • 進入條件 - 只能從 Idle 狀態開始回血，且必須站在地面上、按住 Focus，而且靈魂量要大於每次回血的消耗量。
  • 回復量 - 每次進入 HealGet 會扣除所需的靈魂量，並回復 1 格血。不過實際遊戲其實是在進入 HealStart 的狀態就開始消耗靈魂，直到消耗達標才回血，這邊算是解略版。
  • 行動限制 - 回血時角色水平速度歸零，也不能轉身、跳躍、攻擊。

受傷擊退（Recoil）

當受到傷害後，小騎士會進入 Recoil 狀態，物理上會被往後擊退並微微騰空，除了被擊中的白光特效，另一個特別的就是會朝兩側噴出粒子特效，且會維持一段時間慢慢消失，這是為了讓玩家注意到自己受傷了，這個特效與之前的差異在於它只有噴出時與玩家座標有關，但之後小騎士的移動不該影響到粒子的位置，因此得設定 simulation space = world:
此外這邊不能再透過 animation 來控制粒子系統的 activate，因為動畫播完時，粒子系統還得繼續保持 activate，所以這邊會透過 animation event，也就是下圖中的戳記，他能夠讓 animation 播放時主動呼叫一個自己物件的 public 函數，也就能夠觸發粒子系統的播放 ~~~

靈魂系統（Soul）

Soul Container

靈魂容器是目前我看到最有趣的部分 !!! 可以看到他的 sprite 竟然是方形的，而不是遊戲中的圓形，這也算合理，如果是圓形就沒辦法做到水位動態顯示了，這邊是得透過 shader 來進行圓形遮罩，重點就是在於先產生一個圓形的 filter 與透明度相乘，剩下就是根據當下水位來動態控制 y 軸 offset，此外也替 RGB 呈上亮度係數 (GlowScale) ，方便在靈魂不足以恢復時把亮度降低來提示玩家:

成品


影片中展示了面具的破碎與恢復、Focus 回血、碰到尖刺的擊退，以及攻擊靈魂圖騰吸收 Soul 的效果。即便弄了這麼多還是有很多細節沒有處理，例如: 面具 IDLE 時的同步閃爍、靈魂水位達標時會顯示出眼睛、靈魂全滿後會顯示出另一張 sprite 等等，真是佩服 team cherry 對細節的掌控 !!!
